# Design to demo matrix

This matrix lists the design elements of four sources:

- the Globaal Ontwerp (GO),
- the Project Start Architectuur (PSA),
- the functional requirements for DvTP (FR-DvTP v0.9),
- the EUDI regulation.

For each element, the matrix
records if the [GBO demo](https://github.com/ICTU/GBO-demo) covers it,
and gives the evidence. The [findings](findings.md) and the
[open questions](open-questions.md) give the reverse direction, from demo
to design.

Each row has a status, an evidence link, and a note on the state of the
demo. The notes link to the requirements, findings, open questions, demo
increments, and ADRs that explain the row. The port to the TO on
November 2, 2026 brought the evidence and the notes up to demo
[v0.9.0](https://github.com/ICTU/GBO-demo/tree/v0.9.0). No status
changed.

Of the 111 in-scope rows, 17% are covered, 67% are partial, and 16% are
not covered.

Most partial rows can become covered only after a governance decision or
with production infrastructure. Three examples of such rows are:

- the LDV schema and retention ([Q-08](open-questions.md#q-08)),
- the link of organization identifiers in PSA S04,
- PKIoverheid certificates instead of the demo CA (the direction is
  answered in [Q-07](answered-questions.md#q-07)).

Three items of concrete demo work are open in demo v0.9.0:

- validate a policy set before activation ([F-52](findings.md#f-52)),
- admission per service ([#382](https://github.com/ICTU/GBO-demo/issues/382)),
- the BSN in the ASI token ([#595](https://github.com/ICTU/GBO-demo/issues/595)).

## Legend {#legend}

The status column uses five symbols:

| Status | Meaning |
|---|---|
| ✓ | Covered: the feature works end to end in the demo, with evidence. |
| ◐ | Partial: some parts are covered, and the rest is open. |
| ○ | Not covered: in scope, but not built. |
| — | Out of scope or hook: deliberately not in v1. |
| ? | To be checked against the demo. In demo v0.9.0, no row has this status. |

The scope column uses five values:

| Scope | Meaning |
|---|---|
| Base | The shared foundation for all routes: PEP, PDP, PIP, connectivity, audit, and semantics. |
| DvTP | Specific to the consent route (data sharing with third parties). |
| EUDI | Specific to the EUDI wallet routes: issuance (PuB-EAA) and verification for QTSPs (ASI). |
| Hook | Not in v1, but the demo keeps an extension point open. |
| Out | Not relevant for the v1 demo. |

The evidence column follows three rules:

- A status is valid only with evidence. The evidence is a link to the
  demo at [v0.9.0](https://github.com/ICTU/GBO-demo/tree/v0.9.0), a demo
  pull request or issue, or a requirement that carries the evidence.
- Some links pin an older demo commit. They are historical evidence for
  the state at the time of the check.
- FR-DvTP v0.9 is not public. The matrix names its criteria without a
  link.
